# Yumingxing 在线产品图册

独立运行的餐厨具图册：React + Vite 前台和线上内容管理页面发布到 GitHub Pages，产品内容通过 GitHub 仓库保存。原有 Node.js 24 后台与 SQLite 数据库仍可在本机使用。**不依赖 Codex Sites、Cloudflare 或 ChatGPT 登录。**

客户访问地址：[打开产品图册](https://qiao13822919184-byte.github.io/yumingxing_catalog/)。管理地址：[打开线上管理系统](https://qiao13822919184-byte.github.io/yumingxing_catalog/admin/)。线上提供产品浏览、了解清单、CSV/PDF 导出与 WhatsApp 入口，发布成功后不需要您的电脑持续开机。

## 直接在线管理与发布

1. 打开上方 `/admin/` 管理地址。首次按页面说明，在 GitHub 创建仅授权 `yumingxing_catalog` 仓库、具有 **Contents: Read and write** 权限的 fine-grained personal access token。
2. 将令牌粘贴到管理页的连接输入框。令牌仅在当前页面内存中使用；刷新或退出后需要重新输入。**不要把令牌发送到聊天、写入仓库或粘贴到公开页面。**
3. 编辑产品、分类、图片、组件行及页面设置，检查预览，点击“暂存”将修改保留到当前编辑会话。
4. 点击 **发布到网站**，将整批修改和新图片作为一次提交写入 GitHub。等待 [Pages 工作流](https://github.com/qiao13822919184-byte/yumingxing_catalog/actions/workflows/pages.yml)部署成功，再刷新客户图册。

线上管理使用 GitHub 令牌，**不能用本地 `admin` 账号和密码登录**。尚未发布的编辑只在当前页面中，关闭或刷新会丢失。发布遇到版本冲突时不会强制覆盖他人更新，先保留自己的编辑资料，再重新连接最新版本。

仓库是公开的；其中的草稿资料和上传图片也可从仓库读取。“草稿”只表示不进入客户产品列表，不表示保密。不要将内部报价、客户资料或密码写入产品字段。完整的令牌设置、故障处理和恢复步骤见 [线上后台使用说明](GITHUB_ADMIN_CN.md)。

## 在这台电脑使用

双击项目根目录的 **启动图册.cmd**，首次会安装依赖并构建，然后后台启动服务。

- 前台：http://127.0.0.1:3000
- 后台：http://127.0.0.1:3000/admin
- 初始账号：`admin`
- 首次随机密码：打开本机 `.local/admin-access.txt`。登录后可在后台修改。
- 停止：双击 **停止图册.cmd**。停止不会删除产品和图片。

终端方式（Node.js 24 或更高版本）：

```powershell
npm ci
npm run build
npm start
```

开发使用 `npm run dev`，前台为 http://127.0.0.1:5173，接口由 3000 端口提供。

## 本机后台与线上内容的区别

**今后请在上方线上管理地址维护客户看到的产品。** 仓库 `main` 分支的 `content/catalog.json` 是线上图册的内容来源。本机 SQLite 保留独立使用，不与线上自动同步；本机保存、`git pull` 和重启服务都不会相互同步两边的数据。

项目里的 **发布前台.cmd** 现在提示线上管理入口，请打开所示地址继续。旧脚本已停止从本机数据库推送产品，避免较旧的本机资料覆盖线上更新。`npm run export:public` 仅用于生成本机离线快照；`npm run build:pages` 始终按仓库 `content/` 重新构建。单独执行这两个命令都不会发布到 GitHub。

GitHub Actions 在 `main` 更新后校验内容并部署；部署成功后客户刷新网址即可看到更新。数据库、管理员密码、会话、客户清单和本机 `data/media/` 不会上传。需要迁移另一套本机资料时，应先备份并对照线上最新内容，明确选择需要迁移的产品与图片，不能把旧数据库整体覆盖到仓库。

## 已实现的前台

- 中英切换、电脑和手机布局、统一图片比例，完整展示产品不裁切。
- 分类卡片、分类筛选、名称/型号/SKU/组件搜索、材质筛选及排序。
- 多图产品详情、组件参数、自定义属性、可排序的文本/图片详情块。
- 产品名称下方 `+ 加入了解清单`，当前浏览器本地记录，可填写意向数量和备注。
- 真实 CSV 表格与多页 PDF 清单，包含唯一识别码、原货号、型号、双语名称、完整组件及自定义参数。
- WhatsApp 号码初始为 **+86 159 9257 7610**，在后台页面设计中可修改。
- 下载 PDF 后，支持的设备可通过系统分享面板分享；不支持时保留文件下载。

WhatsApp 直连会预填文字，用户仍需点击发送。它不能自动附上 PDF/CSV；文件由客户通过系统分享或聊天附件按钮选择。网页不能保证消息送达。PDF 使用图片化页面以确保中文显示，支持查看与打印，文字不支持直接复制搜索。CSV 可在 Excel 中编辑，不是 XLSX。

清单保存在浏览器 localStorage，不同步到其他设备；清除浏览器数据会清除清单。业务员根据清单另行报价，前台不显示价格。

## 后台可以自行修改什么

1. **产品管理**：新增、编辑、删除、草稿/上架、核验状态、分类、排序、双语名称与说明、原货号与型号。
2. **产品图库**：上传主图、添加多张实拍图、调整顺序；支持 PNG/JPEG/WebP，单张最大 8MB。
3. **套装组件**：任意增删与排序，每行独立保存中英文名、材质、尺寸、重量、厚度、数量和单位。4 件变 9 件不需要改代码。
4. **详情扩展**：新增自定义参数行、文本说明块、图片块，自行调整顺序。
5. **分类管理**：新增分类、修改双语名称、封面、描述、排列顺序。删除被引用分类前，先迁移其中产品。
6. **页面设计**：品牌显示名称、双语标题、强调色、桌面产品列数等可编辑，并可预览。
7. **数据与账号**：本地后台支持 JSON 导入/导出、完整本地备份、修改管理员密码；线上后台用 GitHub 提交记录保留已发布版本，令牌在 GitHub 管理。

这套后台提供内容、详情模块和页面风格编辑；更彻底的版式变化可以直接修改仓库里的 React/CSS，代码和数据库都由您控制。

## 唯一货号规则与初始资料

当前资料来自 2026-09-06 的 v9 英文图册和对应报价表：81 个图册编号，其中 80 个产品系列上架，1 个柄纹参考保留在后台；包含 300 行组件参数、6 个包装选项、88 张原图。此前的 110 条产品已从线上目录整体替换，旧版本可在 Git 历史中恢复。新安装的本地种子也使用 v9；已有本地数据库保持独立。

v9 使用唯一询盘码 `YMX-REF-001` 对应原图册 `Ref. 001`，`model` 保留原资料型号，其他历史货号保存在自定义参数中。同型号的不同 Ref 分别识别；Ref.112 的银色和金色按原表合为一个系列，用图库和工艺参数说明，询盘时在备注注明工艺。组件 ID（如 `001-01`）和包装选项编号（如 `008-P1`）与报价表逐行对应。这些网站询盘码不代表重新认定工厂正式型号。详见 [v9 导入说明](CATALOGUE_V9_IMPORT_CN.md)。

已有 SKU 不允许直接改动，以免客户旧清单指向错误产品。正式货号可以保存在原货号字段；需要另一种款式时新增独立产品及 SKU。未核验产品必须先确认资料，再标记 Verified 和上架。

## 数据存在哪里

| 路径 | 用途 | 提交 GitHub |
|---|---|---|
| `app/`、`server/`、`scripts/` | 前后台逻辑、部署与测试 | 是 |
| `app/data/catalog.json` | 首次初始化的产品资料 | 是 |
| `public/catalog-products/` | 初始产品图片 | 是 |
| `content/catalog.json` | 线上管理与 Pages 构建使用的完整产品资料、分类与页面设置 | 是，包括草稿 |
| `content/media/` | 仓库产品内容引用的上传图片 | 是，公开可读 |
| `publication/` | 构建过程中生成的客户图册快照 | 由构建生成，不是线上编辑的数据源 |
| `data/catalog.sqlite` | 正式产品、分类、页面设置、管理员、会话、审计 | 否 |
| `data/media/` | 后台上传的产品图片 | 否 |
| `data/backups/` | 完整自动备份 | 否 |
| `.local/` | 初始密码、日志和服务进程信息 | 否 |
| `dist/`、`dist-pages/`、`node_modules/` | 本地生成内容 | 否，可重新构建 |

服务器启动、每日运行、导入/删除前会生成本地完整备份，保留最近 10 份。手动备份：`node scripts/backup.mjs`。备份包含数据库和上传图片。

**JSON 导出只包含数据和图片路径，不含上传图片文件。** 换电脑时应同时迁移完整数据库与 `data/media/`，或者使用完整备份。不要只复制 JSON 之后丢掉图库。

恢复完整备份：停止服务，先复制当前 `data/` 到安全位置，再用对应备份里的 `catalog.sqlite` 与 `media/` 替换相应内容；清理旧 SQLite WAL/SHM 文件应在服务已停止且已有备份后进行。恢复后使用该备份时的管理员密码。导入 JSON 为按产品 ID 合并更新，不会删除导入文件之外的产品。

## 以后将后台也部署到自己的服务器

`127.0.0.1` 只允许本机访问。现在可在 GitHub Pages 的 `/admin/` 通过 GitHub 接口远程编辑内容；它不是 Node.js/SQLite 的公网服务。若以后需要私密草稿、客户数据库、多人独立账号，或保存后无需等待构建即可更新，可将整套 Node.js 服务部署到自己的服务器并配置 HTTPS。

1. 安装 Node.js 24，克隆本仓库，执行 `npm ci` 和 `npm run build`。
2. 迁移已有 `data/`，或首次启动自动初始化。
3. 用 PM2、systemd、Docker 或其他进程管理器运行 `node server/index.mjs`，在前面配置 HTTPS 反向代理。
4. 通过环境变量设置允许访问来源，例如 `CATALOG_ALLOWED_ORIGINS=https://catalog.example.com`；HTTPS 环境设置 `CATALOG_SECURE_COOKIE=1`。勿使用通配符来源。
5. 对 `data/` 做独立服务器备份。数据库和图片目录必须持久化。

可配置：`HOST`（默认127.0.0.1）、`PORT`（默认3000）、`CATALOG_DATA_DIR`、`CATALOG_LOCAL_DIR`、`CATALOG_ALLOWED_ORIGINS`、`CATALOG_SECURE_COOKIE`。详细架构见 `SYSTEM_DESIGN_CN.md`。
